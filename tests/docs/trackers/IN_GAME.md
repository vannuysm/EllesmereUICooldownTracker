# Runtime responsibilities and in-game verification

## Responsibilities

- `Configuration.lua` classifies already-valid changes into data, layout, appearance, visibility/mouse/lock, and position effects, compares normalized profile candidates with current settings, and notifies subscribers in subscription order. It knows none of its consumers. The composition root subscribes the active profile's automatic save, rank-marker refresh through `Ranks.Check`, tracker synchronization, and the Blizzard settings pages, in that order; the Ellesmere integration subscribes its own page refresh. `Configuration.Set` handles scalar controls; `Configuration.Changed` handles editors that mutate a list/map in place. Validation, schema ranges, orientation/growth normalization, and saved-field repair remain exclusively in `ProfileValidation.lua`; FCT1 serialization remains in `ProfileCodec.lua`.
- `Profiles.lua` manages the account library, active-profile assignments, profile snapshots, and profile application, and notifies library subscribers after library changes. Automatic saves merge validated edited fields into the active profile, preserving shared/imported fields that this character has not applied yet. Login restores the latest valid profile before tracker initialization, retaining personal positions. Profile loads, initialization, position changes, and temporary editing state never save back to the library. `ProfileUI.lua` renders the native Ellesmere profile pages and dialogs.
- `Collection.lua` owns spell-name and bag caches, item matching/counts, reusable per-unit aura snapshots, protected aura-delta parsing and instance queries, and cooldown-state collection. It owns no frames or saved data. Unknown aura positions and secret ownership remain unknown, rather than becoming missing buffs.
- `Database.lua` owns saved-variable reconciliation, defaults, migrations, invalid-field repair, character reset, and storage accessors, without depending on profiles, configuration, or collection. Reset clears the character's settings and its account-wide active-profile assignment. `Defaults.lua` owns class presets. The live character table retains its identity when late saved data arrives.
- `EllesmereUICooldownTracker.lua` composes the addon: it loads settings and restores the active profile, subscribes configuration listeners, initializes frames/polling once, routes game events, coalesces updates, and dispatches configuration effects through each tracker's `Init`, `Root`, and `ApplyConfiguration` interface. Each tracker's `Update` takes `renderOnly` first, followed by its feature's event payload. `TrackerFrames.lua` shares root lookup, position saving, root creation, dragging and directional layout. `TrackerAppearance.lua` styles tracker widgets, optionally inheriting an Ellesmere Action Bar's fonts, colors and borders.
- `Cooldowns.lua`, `Buffs.lua`, and `Reminders.lua` own their runtime frame pools, dirty state, and collection/rendering helpers. Cooldowns resolve configured rows; reminders cache learned alternatives/labels. Layout and appearance are independent of cooldown state and aura collection. Buff assignment resets clear duration objects, synthetic state, countdowns, and surplus frames. Casts retain synthetic ground-effect/recast timers, including casts while hidden. Hidden trackers defer rebuilding; visibility transitions collect current data before rendering. Countdown text is checked at most every 0.1 seconds and formatted/written only when its displayed value changes, with no hidden-text formatting. Native duration objects still animate bars.
- `TrackerPreview.lua` owns cached preview resolution, simulated timers, and its own widget pools, built from the trackers' callback-free constructors and the shared reminder layout. The runtime trackers contain no preview behavior. `Settings.lua` owns Blizzard settings pages and settings routing; their sliders use schema ranges. `Commands.lua` owns slash commands and the addon-compartment callback. The Kit family separates base pages, UI primitives, catalogs/search, lists, per-class picks, profile editing, saved-data utilities, and Edit Mode overlays.
- `EllesmereIntegration.lua` owns optional plugin registration, preview headers and affected page invalidation. `EllesmereWidgets.lua`, `EllesmereSettings.lua`, and `EllesmereUnlock.lua` own editors, tracker pages and Unlock Mode callbacks respectively. Their controls use the coordinator and schema ranges. The integration refreshes an active page when changes came from elsewhere or change its structure; its own slider/color callbacks retain active widgets. Unlock discard restores dimensions in one coordinator notification.
- `Ranks.lua` retains ownership of combat deferral and automatic upgrades. A configuration check now collects outdated slots once and shares that result with marker rendering.

Profile commits preserve DB/section identities, account profile/icon references, character ownership, timestamps, positions, and Edit Mode layouts. Position writes update the active Edit Mode layout; profile imports never import positions. Profile loads invalidate dependencies, refresh page caches, and reconcile rank markers. Appearance-only profile changes defer resolution work until the next required data refresh.

## Dependencies and polling

Bag resolution invalidates on `BAG_UPDATE_DELAYED`, item-info arrival, login/world transitions, and profiles. Spell/known/pet resolution invalidates on spellbook/learning events, pet and pet-bar changes, form/override/icon changes, specialization/trait changes, login/world transitions, and profiles. Configuration list changes invalidate their tracker resolution/compiled alternatives and previews. Per-unit aura/connection events invalidate only that unit; roster changes invalidate party/target snapshots, target changes invalidate the target, and death/respawn events invalidate the player. Buffs and reminders share the player's full snapshot.

Cooldown event bursts run once on the next frame. Readable spell/base IDs permit targeted collection; nil/legacy payloads, shared categories, recovery categories, and item-associated casts refresh all relevant state. Sweeps request completion refreshes. Keep the existing 0.5-second active-cooldown fallback (restricted timing/missed completion), 0.2-second visible range check, and two-second aura/ally-range safety refresh. Native timers are only polled at expiry, with at most one retry per 0.2 seconds. Failed/unreadable bag collection retries through the two-second safety callback only while visible; normal cooldown/appearance updates do not poll bags. Optional inherited cooldown appearance keeps the existing two-second refresh because the adapter has no documented change notification for external Action Bar settings.

The visible range check also repairs shown cooldown icons whose native `GetRect()` returns no bounds, even if `GetPoint()` still reports an anchor. It reapplies only the anchor, preserving the cooldown and appearance. Icons with resolved bounds are not repositioned on each tick.

## In-game verification and compatibility limits

Enable Lua errors with `/console scriptErrors 1`. Repeat on the supported Forever client and each supported retail build, both without EllesmereUI and with the relevant Ellesmere/Action Bars modules installed:

1. Change enablement, lock state, visibility, orientation/growth, dimensions, fonts/colors/borders, and tracked entries in each settings UI. Use `/euict cdsize`, `/euict barwidth`, and `/euict barheight`; repeat via successful profile loads. Check matching tracker results, visible settings/previews, green lock backgrounds, right-click settings, and permitted/prevented dragging. Keep dragging sliders/color pickers continuously to verify they remain responsive. Invalid profile/slash values must report validation errors without applying them. Without EllesmereUI, also check range dimming, ready glows, buff visibility, buff orientation/growth, and buff icon/name/time on the Blizzard pages. Reset all settings, from the button and `/euict reset`, with a profile active: after the reload, settings must be defaults with no active profile, and the saved profile must remain in the library. Edit a saved variable to an invalid value and reload: only that field must return to its default, with a chat line naming it.
2. Move each tracker using normal dragging, Blizzard Edit Mode, and Ellesmere Unlock Mode. Save/discard Unlock Mode dimensions; switch Edit Mode layouts and reload. Check positions, active-layout persistence, profiles leaving positions alone, and lock backgrounds after profiles. Check sample entries on empty unlocked trackers and combat entry/exit while unlocked.
3. Carry/add/remove potions and healthstones, use shared item cooldowns, learn/unlearn spells, change ranks, switch pets/pet abilities, forms, specs, and spell overrides. Check icons/counts/order without reloading. Through each settings UI, remove the first of two tracked entries: the second must stay in the saved list and appear as the sole icon on the bar. Add the removed entry back and confirm both icons appear without reloading or manually reapplying anchors. Repeat in and out of combat, with ready spells and active cooldowns. Also remove the second entry while the first is on cooldown: the first must stay visible with its sweep/countdown continuing, then become ready normally. Repeat with reordering and clearing/repopulating the list to check pooled icon reassignment and cleanup. Hide cooldown/buff trackers, change their data, then reveal them and verify current state. Test target range dimming, ready glows, GCD/shared cooldowns, native sweep completion, and restricted cooldown polling.
4. Repeat [buff-state checks](BUFF_STATE_VERIFICATION.md): active/inactive entry reorder/removal/profile replacement, surplus-frame cleanup, unchanged-entry duration retention, prefixes, unreadable queries, recasts, synthetic timers, and expiration. Also hide a tracker during a ground-effect cast, reveal it before expiration, and confirm the remaining timer. Check native bars with readable and real secret timings; hiding timer text must leave animation running.
5. Test self/ally alternatives, own versus another caster's buff, class-specific blessings and fallback lists, party/target deduplication, ally range/connection/death changes, stable ordering, and actual restricted/secret aura data. Unknown data must not create a false missing-buff line. Reminders must disappear immediately on combat entry and return with current data afterward.
6. Verify outdated-rank markers after profiles, keep-list changes, rank enablement, paged action bars, and newer learned ranks. Automatic upgrades must wait for combat to end and must leave an occupied cursor alone.
7. Check optional Action Bar font/border/glow inheritance, then change its settings externally. Verify standalone fallback appearance and behavior with those modules absent. Native glow shutdown, frame-pool reuse, and secret-value behavior require real-client checks.
8. Open **Cooldown Tracker > Manage Profiles**, `/euict profiles`, and the standalone **Open Manage Profiles** button. Check the **Profiles** and **Import / Export** tabs, persistent active-profile banner, class labels, and row menus. Save as, use, rename, duplicate, export and delete profiles; reject name collisions and confirm deletion. Scalar controls, colors, tracked-list edits/reordering, blessing mappings, rank options, slash commands, and Unlock Mode resizing must automatically update the active profile. Save as must direct subsequent edits to the new profile. There must be no Modified state, manual-save control, or unsaved-change switch prompt; the active row remains Active with Use disabled. Unnamed settings must still persist per character without creating a profile. Moving trackers, preview/editing state, aura/cooldown events, and runtime refreshes must not update the saved profile. Discarding Unlock Mode dimensions must restore the saved profile's dimensions too. On another character or after reload, the latest shared profile must apply while retaining personal screen positions and Edit Mode layouts. Rename/delete active profiles and verify assignment restoration on login. Import overwrite must leave current settings intact until Use now or the next login; a subsequent settings edit must preserve other imported fields. Invalid saved profiles must report errors and retain current settings. Check export selection, Ctrl+C, scrolling, import preview, duplicate Overwrite/Keep both/Cancel, draft retention, and optional Use now. Close the panel or press Escape with a dialog/menu open; it must dismiss without changing data. Verify that tracker previews and the profile banner do not overlap when switching modules. With EllesmereUI disabled, `/euict profiles` must open the standalone page and settings edits must still automatically update the active profile.

The profile guidance beneath the tabs must stay the same after actions. Use, save, rename, and delete should show their results through the rows and active-profile identity, without additional success announcements. Import/export errors must appear beside their controls and must not carry over to the Profiles tab. Editing an invalid import or choosing a different export source clears the relevant old error.

Preview a profile whose name matches its class, such as a Paladin profile named Paladin. The preview must label **Name**, **Class**, and **Tracked** separately, so identical values remain understandable. Profiles without class metadata must show **Class: Not specified**.

The **EXPORT** section uses a **Profile** dropdown and fills its text box automatically on opening the tab and on selection; there is no Generate export button. Check immediate Ctrl+C copying after selection and click-to-select-all on the export text. Selecting a different profile must preserve an unfinished import draft and avoid rebuilding the page. An invalid export selection must clear the old export text, so a different profile's text cannot be copied by mistake. Export from a library row must open this tab with that profile's text ready.

The adapter uses the published [Ellesmere plugin API](https://github.com/EllesmereGaming/EllesmereUI/blob/main/PLUGINS_API.md) for registration, module keys, opening settings, and page invalidation. The old private `_ELEMENT_SETTINGS_MAP` write was removed: the documented plugin API has no unlock-cog-to-plugin mapping hook. That cog's direct **Element Options** link is therefore unavailable for these trackers; use tracker right-click, `/euict cd`/`buff`/`remind`, or the Ellesmere sidebar. Public unlock registration/listener callbacks remain guarded as before; their [upstream registration API](https://github.com/EllesmereGaming/EllesmereUI/blob/main/EUI_UnlockMode.lua) is separate from the plugin API.

Cooldown targeting follows Blizzard's documented [spellbook event payloads](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpellBookDocumentation.lua); aura updates follow [UnitAura documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitAuraDocumentation.lua). Missing optional APIs fall back to existing readable timing/manual bar behavior. The inherited forty-aura and bag 0-4 bounds remain unchanged. No in-game performance or protected/secret-value compatibility claim is made from the mock tests.
